# 结构指南：三段式与分类维度

## 一、三段式骨架（所有场景通用）

每一份汇报都由三段组成，顺序不可颠倒：

1. **事实（Facts）**：本周期做了什么。只写已完成或已产生可验证进展的事，每条可回溯到原料。
2. **价值（Value）**：这些事实意味着什么。回答"所以呢"——解决了什么问题、支撑了什么目标、带来了什么可观察的变化。价值必须锚定在事实上，不允许独立存在的"价值句"。
3. **计划（Next）**：下周期要做什么。计划条目尽量与本期事实衔接（"完成 X 的联调"承接"X 开发完成"），并标注风险或依赖。

> 原则：事实段占全文 50% 以上。价值段宁缺毋滥，没有就不写，绝不用套话凑数。

## 二、分类维度（第 2 步归并用）

把原料归入 3–5 个主题板块。常用维度（按岗位选用）：

| 维度 | 典型板块 | 适用人群 |
| --- | --- | --- |
| 按工作性质 | 需求开发 / 问题修复 / 技术建设 / 协作沟通 / 学习调研 | 工程师通用 |
| 按项目 | 项目 A / 项目 B / 公共事务 | 多项目并行者 |
| 按目标 | 目标 1 进展 / 目标 2 进展 / 目标外工作 | OKR/KPI 驱动团队 |
| 按角色 | 个人产出 / 团队协作 / 带人育人 | 技术负责人 |

板块数不超过 5 个；条目不足 2 条的板块合并到「其他」。

## 三、三种场景的差异

### 周报（weekly）

- 读者：直属上级，快速浏览
- 篇幅：300–600 字
- 重点：事实 + 下周计划，价值段可压缩为每板块一句话
- 语气：平实，允许口语化

### 月报（monthly）

- 读者：上级 + 隔级，可能存档
- 篇幅：600–1200 字
- 重点：增加数据汇总（完成需求数、处理缺陷数、关键里程碑），事实按周分组可追溯
- 价值段不可省略，需对应月度目标

### 述职 / 绩效素材（review）

- 读者：评审者，目的是证明贡献
- 篇幅：不限，按「目标 → 行动 → 结果」组织
- 重点：每个板块是一个完整论证单元：
  - **目标**：当时面对什么问题/指标
  - **行动**：自己（而非团队）做了什么决策和动作
  - **结果**：可验证的结果（数字、上线、他人采用）
- 区分「我主导的」「我参与的」「团队共同的」，不混用主语

## 四、原料映射（可追溯性）

成稿末尾附原料映射表：

```
| 板块 | 结论条目 | 原料编号 |
| --- | --- | --- |
| 需求开发 | 完成订单导出功能 | #3 #7 #12 |
```

作用：评审追问时可当场出示证据；用户自查时可发现"写进去的其实没做"。
